# Рекламный сценарий

## Настройка

1. Администратор выбирает проект с подачей и открывает «Настройки → Рекламный сценарий».
2. Выбирает ботов, отдельный тег рекламной аудитории, защитные теги (например HOT HOT) и время перехода. По умолчанию 180 минут. Целевые лиды по настройкам трекинга также защищены.
3. В разделе «Слоты» создаёт посты, задаёт порядок и интервалы, проверяет предпросмотр и включает необходимые слоты. Позиции сортируются по возрастанию, начиная с 0. При одинаковой позиции порядок стабилен, но лучше задавать разные.
4. Сценарий включается явно. Существующие чаты сами в него не попадают. Если активных слотов нет, основной сценарий не останавливается; проверка повторяется через 5 минут.

Один слот содержит один пост: текст или медиа с подписью и кнопками-ссылками. Запуск других воронок из рекламных кнопок запрещён. Для медиа используются загруженные файлы, а не file_id чужого бота.

## Автоматическая работа

- После нового запуска основной воронки начинается таймер. Повторный /start этот таймер не переносит.
- По истечении таймера проверяются целевой статус/теги, защитные теги, доступность чата и ручная пауза менеджера.
- Подходящий чат получает рекламный тег; основная воронка ставится на паузу, её отложенные задания отменяются. Карточка, история и существующие теги сохраняются.
- Состав, порядок и интервалы очереди фиксируются при переводе в рекламу. Первый пост отправляется в ближайшем цикле обработчика, следующие после своего интервала от завершения предыдущей попытки.
- Правки содержимого ещё не отправленного слота подхватываются перед отправкой. Отправленные посты не редактируются. Новые слоты не добавляются уже сформированной очереди. Выключенный слот пропускается.
- После последнего слота чат остаётся рекламной аудиторией. Для обычной рассылки доступно условие «Рекламная аудитория». Перед её отправкой защита проверяется повторно.
- Автоматический возврат возможен только по явному /start после 30 дней без входящих сообщений лида. Запускается актуальная основная воронка; оставшаяся реклама отменяется. Снимается только рекламный тег, добавленный этим сценарием; ранее существовавший тег сохраняется.
- Отключение сценария приостанавливает обработку его очередей, не стирая историю. При включении просроченная очередь продолжится, интервалы между следующими отправками сохранятся. Для окончательной отмены используйте остановку участника.
- Исключение конкретного бота из настроек останавливает его ожидающие очереди при следующей проверке. Повторное включение бота их не восстанавливает.
- Ручной административный сброс диалога отменяет старую рекламную очередь. Пользовательские команды и кнопки старого движка не должны обходить рекламную паузу.

## Старая база

Вкладка «Старая база»: выбрать дату создания чатов, отдельно указать «Остановить основную воронку» и «Запустить слоты», затем проверить аудиторию. Запуск требует слова ЗАПУСТИТЬ и действующего предпросмотра (15 минут). Изменение настроек требует нового предпросмотра.

Только маркировка не отправляет посты и не останавливает основную воронку. Запуск слотов требует остановки основной. Обработка идёт порциями по 25; защита проверяется ещё раз перед изменением каждого чата. Повторное подтверждение не создаёт второй прогон. Уже учтённые участники не добавляются повторно, в том числе после режима «только маркировка». Для них можно использовать обычные рекламные рассылки.

## Отдельный Telegram-бот

Суперадминистратор подключает отдельный токен во вкладке «Telegram-бот». Нельзя использовать инфобота, баер-бота или бота воронки. Токен хранится зашифрованным; нужен существующий ключ шифрования CRM.

Доступ только суперадминистраторам с привязанным Telegram ID, в личной переписке. /start → проект → слот. Можно менять текст, медиа, URL-кнопки, интервал и включение слота; изменения применяются только после «Сохранить». Фото/видео/документ можно прислать боту (до 20 МБ), более крупные файлы загружаются через CRM. Создание и порядок слотов настраиваются в CRM. Одновременное редактирование защищено номером версии: устаревший черновик не перезаписывает новый.

## Трекинг и диагностика

«Трекинг → Реклама»: период по МСК, фильтр бота, состояния участников, результаты отправок по слотам и первоначальные источники. Период относится к регистрации в сценарии, не к дате каждой отправки. После возврата через 30 дней человек может иметь новый цикл; считаются циклы, а не уникальные Telegram ID.

Это отчёт по очереди и доставке. Он не измеряет прочтения или клики по внешним рекламным кнопкам. Для переходов можно использовать отдельные трек-ссылки в самих постах.

В «Участниках» доступны история слотов, ошибки и остановка очереди. В «Журнале» фиксируются настройки, изменения постов, переходы и прогресс старой базы.

Перед обращением к Telegram фиксируется попытка отправки. При сбое между отправкой и сохранением ответа результат помечается uncertain: автоматического повтора нет, чтобы не задублировать рекламу. Это может привести к пропуску поста, а не гарантировать exactly-once. Подтверждённые ошибки Telegram сохраняются как failed; недоступный аккаунт останавливает оставшуюся очередь. Следующий слот после пропуска/ошибки идёт с заданным интервалом.

Явный ответ Telegram 429 откладывает тот же слот на retry_after: это не потеря результата, а подтверждённый отказ из-за лимита. Настройки и защита заново читаются перед отправкой. Уже начатый сетевой запрос нельзя отозвать: изменение настройки или тега во время самого запроса не гарантирует отмену этого одного сообщения.

## Выкладка

1. Сделать резервную копию БД и проверить возможность восстановления. Файлы рекламных постов хранятся в существующем томе broadcast_uploads_data; SQL-бэкап сами медиафайлы не содержит.
2. Проверить текущую ревизию БД. Новая миграция 20261030_0090 следует за 0089 и создаёт только новые таблицы/индексы. Она не обновляет старые чаты. Применить её до запуска нового API/обработчиков.
3. Собрать frontend и сервер, перезапустить API и worker. Стандартный режим worker all уже включает очередь advertising и отдельного бота advertising-bot. При раздельном запуске обработчиков добавить оба режима явно.
4. Всё оставлено выключенным по умолчанию. Сначала проверить отдельного тестового бота: переход, защищённый тег, два слота, редактирование до отправки, повторный /start, остановку.
5. Только после проверки включить рабочие проекты. Старую базу запускать отдельно после проверки предпросмотра.

`deploy-dev.sh` теперь собирает образы, останавливает перечисленные обработчики, создаёт закрытый дамп в `backups/deploy`, применяет миграции отдельным контейнером и только затем запускает новый код. При ошибке бэкапа или миграции запуск прерывается; приложение остаётся остановленным. Скрипт привязан к dev-серверу и ветке dev: не переносить его в production без адаптации. Если на сервере есть обработчики вне перечисленных Docker-сервисов, их также необходимо остановить вручную.

Дампы исключены из Git и Docker-контекста. Они не удаляются автоматически: контролируйте свободное место и переносите копию на другой сервер/хранилище. Дамп на том же диске не защищает от потери сервера. Отдельно сохраняйте медиа-тома и конфигурацию/ключи шифрования: восстановить только SQL недостаточно для полного переноса CRM.

Откат схемы специально не удаляет рекламную историю. Сначала выключить сценарии и рекламного бота, остановить обработчики; не откатывать миграцию удалением таблиц. Старый код не знает рекламных пауз, поэтому откат приложения после начала рабочих прогонов требует отдельного плана сохранения состояний.

Локально проверяется применение 0090 поверх текущей схемы с существующим проектом. Полная цепочка миграций с нуля имеет отдельную старую проблему в 0012 (повторное добавление waiting_for_answer); это не исправлялось в рамках рекламного сценария.

## Локальные проверки

Обычный набор: `.venv/bin/python -m pytest -q tests`.

Проверки реальных транзакций и миграции: `CRM_TEST_POSTGRES_URL=postgresql+asyncpg://... .venv/bin/python -m pytest -q tests/test_advertising.py`. Использовать только отдельную тестовую БД: тесты создают и удаляют собственные схемы. Отправка Telegram подменена.

Интерфейс: `PLAYWRIGHT_MODULE=/path/to/playwright PLAYWRIGHT_CHROMIUM=/path/to/chromium node tests/advertising-ui.cjs` при запущенном frontend на 5177. API перехватывается тестом; проверяются desktop/mobile, сохранение, подтверждение и отчёт.
