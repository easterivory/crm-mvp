# Свежая выгрузка 06.11.2026, 13:13 МСК

Источник: crm_server_logs_20261106_101348_UTC.txt и скрин формы рассылки.
Последний подготовленный патч ещё не установлен на сервере со слов владельца.
Период заголовка: 09:43–10:13 UTC / 12:43–13:13 МСК; exports.log содержит хвост.

## Рассылка

На скрине аудитория 23 852. BroadcastService требует confirmation="ПОДТВЕРЖДАЮ"
при count > 1000. BroadcastWizard после замены ReviewStep на SafetyStep вызывал
sendBroadcastNow без confirmation; scheduleBroadcast также его не передавал.
Это воспроизводимый отказ 422 независимо от здоровья Telegram/очередей.
HTTP-ответ конкретной production-попытки в выгрузке отсутствует; упоминаний
broadcast нет. Общий catch скрывал причину в интерфейсе.

Исправлено в форме: подтверждение передаётся после удержания для обоих режимов,
серверная защита сохранена. Уход со шага отменяет удержание. При неопределённом
результате сети не повторяем автоматически: сначала проверить список рассылок.

Изображение на пользовательском скрине выбрано как document: после запуска оно
будет отправлено файлом. Для обычного фото следует выбрать тип photo в контенте.
Это не причина отказа запуска.
