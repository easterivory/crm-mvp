## Confirmed Cause

The builder permits explicit push rules in every project, but the candidate
query required `project_format = gambling`. Therefore submission projects
silently excluded their configured rules from delivery.

| Вакансии | 48 | 7,250 | 16,250 |

Eligibility includes active/waiting/unpaused states, visible/unblocked chats,
elapsed rule delay, unsent visit marker, and delivery suspension checks. Rules
in older pinned versions remain valid; the active-version column is a separate
configuration summary, not the source of the overdue counts.

Вакансии has no retained `push_rules_sent` states or matching push messages.
Латам Гембл has 859 states with retained push markers and 1,720 bot messages
matching configured push text. Its last matching message is 22 September;
there are none in the last 24 hours of this snapshot. This demonstrates past
delivery, not current worker availability. At snapshot time, all 28 eligible
gambling rule rows were already marked sent for their current visits.

Алинка and Узб Гембл have no configured push rules in this backup. Automatic
step delay jobs, broadcasts and manually scheduled messages are separate
mechanisms and were not enabled or rewritten by this fix.

The supplied 30-minute log contains API, backup and jobs logs, without push

## Changes

- Explicitly configured push rules work in both formats. No rules means no
  automatic pushes; no rules are generated by this update.
- The user selected **new step visits only, no historical submission backlog**.
  Migration 0086 adds `projects.funnel_push_enabled_at` with a persisted database
  timestamp. Submission states entered before that timestamp remain excluded.
  A later entry into a step is eligible normally. Gambling scheduling retains
  its existing behavior. API settings and ordinary project edits do not change
  this timestamp.
- Sent markers are excluded in SQL before applying the batch limit. Previously
  older sent rows could fill the first 400 results and hide newer unsent rules.
  This is a confirmed code defect reproduced by a real PostgreSQL regression
  test, not the cause of the submission backlog in this snapshot.
- A once-per-minute scan heartbeat makes an idle push worker visible in exported
  logs. Existing error rollback, separate failure persistence, suspension,
  operational alerts and message/media delivery remain intact.
- The preceding repeated-start fix remains: repeated `/start` does not clear
  unanswered push count or reset the same-step clock/sent markers. A valid
  funnel transition still changes the current step and its schedule.
